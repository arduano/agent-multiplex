# Codex API: data lifecycle

Pin: **0.162.1**, [exact source](https://github.com/openai/codex/tree/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d). Native API facts only. Each row links to its pinned source rationale.

| Data                                                                                                    | Lifecycle / scope                                                                                                                          | Contract boundary                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Connection / RPC](API-Data-Lifecycle-Sources.md#1-connection-and-rpc)                                  | Initialize per connection; requests receive replies; notifications arrive while attached.                                                  | Request IDs correlate replies, not durable effects. Lost reply ≠ rejection. No general event-replay cursor; timestamps do not establish continuity.                     |
| [Thread](API-Data-Lifecycle-Sources.md#2-thread)                                                        | `threadId`; create, read/resume, archive/unarchive, delete. Ephemeral or persistent.                                                       | Creation ACK can precede history materialization. Read is passive; Resume may activate saved work. Archive/delete ACK ≠ process retirement.                             |
| [Runtime state](API-Data-Lifecycle-Sources.md#3-runtime-state)                                          | `notLoaded`, `idle`, `active` with waiting flags, `systemError`.                                                                           | Runtime-relative observation, separate from stored history. Idle/disconnected does not prove all processes stopped.                                                     |
| [Turn](API-Data-Lifecycle-Sources.md#4-turn)                                                            | Thread+turn identity; `inProgress` → completed/failed/interrupted. Start can steer existing work.                                          | Exact steering targets `expectedTurnId`. Exact-turn interrupt waits for abortion, not process retirement. Terminal turns can gain later history.                        |
| [Item](API-Data-Lifecycle-Sources.md#5-item)                                                            | Ordinary identity: thread+turn+item; 19 variants. Realtime items are separate. Starts/deltas/completion and stored upserts expose changes. | Deltas address specific fields/indices. Completed item ≠ successful tool/finished descendants. Stored snapshots are not universally immutable.                          |
| [Stored content](API-Data-Lifecycle-Sources.md#6-stored-content)                                        | Native history is a projection; some tool results are reduced and projection can lag.                                                      | Stored and live bodies can legitimately differ. Preserve representation provenance and coverage.                                                                        |
| [History views](API-Data-Lifecycle-Sources.md#7-history-views)                                          | Metadata, `notLoaded`, `summary`, `full`; stored pages can omit still-streaming items.                                                     | Empty/summary payload ≠ empty/complete conversation.                                                                                                                    |
| [Pages / cursors](API-Data-Lifecycle-Sources.md#8-pages-and-cursors)                                    | Opaque, method/direction/filter scoped. History turns/items/timeline cap at 100; backend/archive support differs.                          | No atomic multi-page snapshot or public read/live watermark. Null next cursor ends that queried direction at that time.                                                 |
| [Settings / plans](API-Data-Lifecycle-Sources.md#9-settings-and-plans)                                  | Thread defaults, turn overrides, applied-setting events. Mode: `default`/`plan`.                                                           | Requested/acknowledged/applied differ. Mode, proposed plan item and progress checklist are independent facts.                                                           |
| [Models / usage](API-Data-Lifecycle-Sources.md#10-models-and-usage)                                     | Catalog, configured selection, execution/reroute/auth events, usage snapshots.                                                             | Catalog ≠ executed model. Usage snapshots are not additive deltas.                                                                                                      |
| [Questions / approvals / callbacks](API-Data-Lifecycle-Sources.md#11-questions-approvals-and-callbacks) | Pending native request → typed reply, resolution/withdrawal. Ordinary pending requests can replay across connections.                      | Runtime+request identity matters. Resolution can precede validation; it proves neither permission granted nor tool completion. Optional message questions are separate. |
| [Queues / goals](API-Data-Lifecycle-Sources.md#12-queues-and-goals)                                     | Persist beyond a turn; dispatch/continuation may occur later, including on Resume.                                                         | Interrupt/disconnect does not remove future work. Queue IDs and message correlation IDs differ.                                                                         |
| [Subagents](API-Data-Lifecycle-Sources.md#13-subagents)                                                 | Separate threads, turns/history and parent/source edges; forks have separate provenance.                                                   | Parent completion ≠ child completion. Lineage and `canAcceptDirectInput` govern interaction; shared session IDs alone do not prove ancestry.                            |
| [Processes / files](API-Data-Lifecycle-Sources.md#14-processes-and-files)                               | Thread terminals, standalone commands and file references have separate lifetimes.                                                         | Turn completion ≠ process exit. A path is not immutable bytes or a retention guarantee.                                                                                 |
| [Config / auth / catalogs](API-Data-Lifecycle-Sources.md#15-configuration-authentication-and-catalogs)  | Separate configuration, credential, MCP/plugin/environment APIs.                                                                           | Persistence/scope are per method. Thread history is not their complete log; capability negotiation is not authorization.                                                |

**Preserve these dimensions:** identity/scope, runtime incarnation, intent versus
observed state, content provenance/coverage, ordering, continuation and each
command's exact completion boundary. The API provides no universal version or
exactly-once guarantee joining them. Consumer cache eviction is not native deletion.
